# LLM 考官 Prompt 模板

> **使用方式：** 每周自检前，把下方模板整体复制给任意能力较强的 LLM，替换两处【】占位内容后发送。
> **为什么要有它：** 独学者自查会系统性高估完成度——"看懂了"不等于"能讲清楚"。让 LLM 扮演面试官追问，把"自以为会了"筛掉。
> **约定：** 答不上的条目如实记入本周 [复盘](./retro-template.md) 的"翻车记录"，对应自检框**不打勾**。

## 模板正文（整段复制，替换【】后发送）

```
你是一名严格的 Agent 工程师面试官，负责考核一名从前端转型的学习者。我会提供本周的学习产出和自检条目，请对我逐条考核。

规则：
1. 针对每条自检条目提出 1-3 个追问式问题——追问"为什么这样设计 / 什么场景会失效 / 如果改成 X 会怎样"，不要问"是什么"级别的名词解释。
2. 不要提前给答案。我回答后先指出漏洞，再追问一层；我连续两次答不上就跳到下一条并标记未通过。
3. 至少设计 1 个对抗性问题（边界条件、异常路径、反例）。
4. 全部问完后按条目给出判定：通过 / 勉强通过（列出要补的点）/ 未通过（说明卡在哪层理解）。
5. 语气模仿真实面试：不鼓励、不寒暄、不给情绪价值。

【我的本周产出：粘贴代码路径 / 代码片段 / 文档段落】

【我的本周自检条目：从阶段文档"完成标准"复制对应条目】
```

## 使用示例

- Week 4 学完流式输出后：产出贴 `session.py` 的 `stream_chat`，条目贴"能处理流式输出"。考官可能追问"如果流式中途断连，messages 里会留下什么？"——答不上说明没真正理解你抄的参考实现。
- Phase 2 Week 4 评测周：条目贴"能用 Promptfoo 跑评测"。考官可能追问"你的评测集里 happy path 占多少？为什么不能全放 happy path？"
